# TBL-007 — Row cell count matches the header

> Category **TBL** (tables) · Scope **document** · Default severity **error** · Fixable **no** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

Every body row of every in-scope table must have exactly as many cells as the header row. TBL-007 reports each row whose written cell count differs, anchored at that row's line, and names both counts.

A malformed row is easy to miss because nothing breaks visibly in the source. When the table renders, cells beyond the header are silently dropped, and a short row is padded with blanks. The other TBL rules read the table the same way — as the header-shaped table, not as what the author wrote — so a row with an extra cell has content no rule can see, and a short row looks to them like a row with empty cells.

The header itself is never reported: GFM only recognises a table when the header and delimiter rows have the same number of cells.

If `section` is set, only tables under a heading whose text matches that section are checked; otherwise every table in the file is checked.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `section` | `string` | no | — | Only check tables under a heading matching this text; omit to check all tables. |
| `files` | `string[]` | no | all included | Glob(s) narrowing which files this rule instance applies to. |
| `exclude` | `string[]` | no | — | Glob(s) removing files from this rule instance. |

## Example

### Config

```jsonc
{
  "rules": [{ "rule": "TBL-007" }],
}
```

### Passes

```md
| ID    | Owner | Note         |
| ----- | ----- | ------------ |
| REQ-1 | Ann   | `a \| b`     |
| REQ-2 | Bob   | either \| or |
```

### Fails

<!-- prettier-ignore -->
```md
| ID    | Owner |
| ----- | ----- |
| REQ-1 | Ann   | urgent |
| REQ-2 |
```

→ TBL-007 reports two findings, each at its row's line: `Row has 3 cells but the header declares 2; the extra cells are dropped when the table renders.` for `REQ-1`, and `Row has 1 cells but the header declares 2; the missing cells render empty.` for `REQ-2`. Each finding's `data` carries `expected` (the header's count) and `actual` (the row's).

## Notes

- **Scope:** `document` — evaluated per file, independent of other files.
- **Escaped pipes:** `\|` is never a cell separator, including inside a code span — `` `a \| b` `` is one cell.
- **Unescaped pipes inside backticks are separators.** GFM splits a table row into cells before it reads inline code, so `` `a|b` `` in a table cell is two cells, and GitHub renders it that way. TBL-007 counts cells the same way the renderer does, so such a row is reported. Escape the pipe as `\|` to keep it in one cell.
- **Pairs with TBL-002.** [TBL-002](TBL-002.md) does not report the missing cells of a short row as empty — the defect is the row, and reporting each padded cell as well would raise two findings for one mistake. A config that enables TBL-002 should therefore enable TBL-007 too, or short rows go unreported. `init` proposes both whenever the corpus contains a table.
- **Other TBL rules still see blanks.** [TBL-003](TBL-003.md), [TBL-004](TBL-004.md), [TBL-005](TBL-005.md) and [TBL-006](TBL-006.md) read a missing cell of a short row as an empty value, so they can report a finding on the same row. Fixing the row clears those too.
- **Not fixable.** Padding a short row could be done deterministically, but for a row with too many cells there is no safe way to choose which cell to drop, so the rule leaves the repair to the author.
- **`files`/`exclude`** narrow which files this rule instance applies to.
