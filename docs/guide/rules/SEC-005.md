# SEC-005 — No duplicate headings

> Category **SEC** (sections) · Scope **document** · Default severity **warning** · Fixable **no** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

SEC-005 reports a heading whose text repeats an earlier heading in the same document. A repeated heading causes two problems:

- A `section` option that names it (in TBL-\*, SEC-\*, CTX-\* or a `custom` rule) is ambiguous. Some rules scope to the first heading with that text and ignore the rest, others take every heading with it, so what the option covers depends on the rule and on heading order rather than on which section you meant.
- Its anchor becomes an order-dependent slug. GitHub gives the second `## Usage` the anchor `#usage-1`, so a link to it breaks as soon as the headings are reordered.

Each repeat is reported once, at its own line, and the message names the line of the **first** heading with that text. A third copy is a second finding that also names the first line.

### What counts as the same text

Headings are compared by their text as rendered, exactly:

- Inline formatting is stripped. `## **Usage**`, `` ## `Usage` `` and `## [Usage](x.md)` all have the text `Usage`, so each repeats `## Usage`.
- Depth does not matter in the default mode. `## Usage` followed by `### Usage` is a repeat.
- The comparison is case-sensitive. `## Usage` and `## usage` are not reported. They still share a slug, but a `section` option tells them apart, and SEC-005 matches what `section` matches.
- Raw inline HTML keeps its tags, so `## <b>Usage</b>` is not the same text as `## Usage`.
- Empty headings (`#` on its own) are skipped.
- Headings inside blockquotes and lists count like any other heading, just as they do for anchor slugs.

Two identical top-level headings are also reported by [SEC-004](SEC-004.md)'s `singleTitle` check. The two findings describe different defects: one title too many, and one repeated text.

### Siblings only

With `"siblingsOnly": true`, two headings are compared only when they are siblings: they have the same depth and the same parent. A heading's parent is the nearest heading above it with a smaller depth, or the document itself if there is none.

```md
## 1.1.0

### Added

## 1.0.0

### Added
```

This passes with `siblingsOnly` because each `### Added` has a different parent. It fails without it. `## A` followed by two `### X` headings fails in both modes, because the two `### X` are siblings.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `siblingsOnly` | `boolean` | no | `false` | Compare only headings with the same parent and the same depth. |
| `files` | `string[]` | no | all included | Glob(s) narrowing which files this rule instance applies to. |
| `exclude` | `string[]` | no | — | Glob(s) removing files from this rule instance. |

## Example

### Config

```jsonc
{
  "rules": [{ "rule": "SEC-005" }],
}
```

### Passes

```md
# Guide

## Install

## Usage
```

### Fails

```md
# Guide

## Usage

## **Usage**
```

→ SEC-005 reports line 5: `Heading "Usage" duplicates the heading on line 3.`

### A changelog with one section per release

```jsonc
{
  "rule": "SEC-005",
  "options": { "siblingsOnly": true, "files": ["CHANGELOG.md"] },
}
```

Each release can have its own `### Added` and `### Fixed`; a release that lists `### Added` twice is still reported.

## Notes

- **Scope:** `document` — evaluated per file, independent of other files.
- **Not fixable:** choosing a new name for a heading is a judgment call, so SEC-005 reports rather than rewrites.
- **Default severity is `warning`:** this is outline hygiene, and the rule is meant to be enabled without options.
- A finding can be silenced with an inline `<!-- wastech-mdlint-disable-next-line SEC-005 -->` on the line before the repeat.
