# STR-001 — Required files exist

> Category **STR** (structure) · Scope **project** · Default severity **error** · Fixable **no**
> · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

The project must contain every path listed in `files`, and STR-001 reports a finding for each
required entry the project does not satisfy.

This enforces repository structure — every project must ship a `README.md`, a `CONTRIBUTING.md`, a
`LICENSE`, and so on. Each entry may be a literal path or a glob, so you can require _that a
category of file exists_ (e.g. at least one `docs/adr/*.md`) rather than one exact filename.

> **Note:** here `files` is the _required set_ — the files that must be present — not a scoping
> filter. Unlike the document-scope SEC rules, STR-001 has no `files`/`exclude` scoping options;
> it always evaluates the whole project.

## How an entry is satisfied

Each entry is classified as a **literal path** or a **glob**, and the two resolve differently:

| Entry                                           | Satisfied when                                                                                         |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Literal — `LICENSE`, `README.md`, `docs/api.md` | a file **or directory** exists at exactly that repository-relative path, whether or not it is Markdown |
| Glob — `docs/adr/*.md`, `assets/*.png`          | some file **in the analyzed Markdown corpus** matches it                                               |

Three consequences worth knowing:

- **A literal entry is pinned to the repository root.** `README.md` means the one at the root; a
  `docs/nested/README.md` does not satisfy it. To require "a README anywhere", write the glob
  form `**/README.md` instead.
- **A glob entry is not root-relative unless it contains a `/`.** A slash-free pattern is matched
  at any depth — `*.md` behaves as `**/*.md`, so a lone `docs/nested/note.md` satisfies it. Add a
  directory segment (`docs/*.md`) to constrain the depth; a glob cannot be pinned to the root, so
  use a literal entry when the location is what you are enforcing.
- **A glob entry cannot see beyond the Markdown corpus.** `assets/*.png` is reported missing even
  when such files exist on disk, because globs are matched against the files `include`/`exclude`
  selected for the run — never expanded against the filesystem. Require a specific non-Markdown
  file by its literal path, which is resolved on disk.

Because a literal entry is checked on disk, STR-001 can require files the linter never parses —
`LICENSE`, `package.json`, `.gitignore`. It only asks whether the path exists; it never reads the
file's contents.

## Options

| Option  | Type            | Required | Default | Description                                                                            |
| ------- | --------------- | -------- | ------- | -------------------------------------------------------------------------------------- |
| `files` | `string[]` (≥1) | **yes**  | —       | Paths or globs the project must contain; each entry unmatched by any file is reported. |

## Example

### Config

```jsonc
{
  "rules": [
    {
      "rule": "STR-001",
      "options": { "files": ["README.md", "CONTRIBUTING.md"] },
    },
  ],
}
```

### Passes

A project containing both `README.md` and `CONTRIBUTING.md` produces no findings.

### Fails

A project containing only `README.md`:

```md
# Readme
```

→ STR-001 reports that required file **`CONTRIBUTING.md`** is missing from the project, anchored at
that path.

### Requiring a category of file with a glob

```jsonc
{ "rule": "STR-001", "options": { "files": ["docs/adr/*.md"] } }
```

Passes as long as at least one file matches `docs/adr/*.md`; reports the glob as missing if none do.

## Notes

- **Scope:** `project` — evaluated once against the whole project, not per document.
- **Glob entries** are satisfied when any file in the corpus matches, at any depth if the pattern
  has no `/`; literal paths must match exactly — relative to the repository root.
- **Path containment:** a literal entry is resolved on disk, so it is held to the analyzed root the
  same way [SEC-003](SEC-003.md)'s `template` is: a relative path whose `..` segments climb outside
  the root — or _any_ absolute path, including one that happens to point back inside the root — is
  rejected with `… escapes the analyzed root and cannot be verified.` instead of being probed. That
  finding is emitted at the same severity as a missing file and is identical whether or not the
  out-of-root path exists, so the required-file list cannot be used to ask whether an arbitrary file
  exists on the host. Containment is lexical — a symlink that lives inside the root but points
  outside it is still probed.
- **Not fixable:** STR-001 cannot know the contents a missing file should have, so it reports rather
  than creating placeholder files.
- Each missing required entry is reported against its own path so results stay deterministic and
  point at the specific gap.
