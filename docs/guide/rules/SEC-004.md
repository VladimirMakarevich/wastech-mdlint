# SEC-004 — Heading levels and title

> Category **SEC** (sections) · Scope **document** · Default severity **warning** · Fixable **no** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

SEC-004 keeps a document's outline well formed with three checks. Each is on by default and can be turned off on its own.

- **`increment`** — heading levels go deeper by one at a time. A heading more than one level deeper than the heading before it (`##` followed directly by `####`) is reported at the deeper heading. Going shallower by any amount (`####` back to `##`) is fine. The first heading in the file is never an increment finding; where the document starts is the `title` check's job.
- **`singleTitle`** — the document has one top-level heading. Every heading at `level` after the first is reported at its own line, and the message names the line of the first one.
- **`title`** — the document starts with a title. It passes when the first block that renders is a heading at `level`, or when the front matter has the `titleKey` key. Otherwise one finding is reported at the first block, such as leading prose, a list or a heading at another level.

### What counts as the first block

Front matter, HTML comments (including `wastech-mdlint-disable` directives and licence banners) and link reference definitions such as `[x]: ./y.md` render nothing, so they are skipped. An HTML block with real markup, such as a badge `<img>` or a centred `<p align="center">`, renders on the page and counts as the first block. A heading inside a blockquote or a list is not a document title, so a document that opens with `> # Quoted` is reported.

An empty document, or one that has only front matter, has no block to point at. Its `title` finding is reported at line 0, which means the whole file.

### Front matter title

The `title` check looks only at whether the key is present. Any value counts, including an empty `title:`. To require a non-empty title, add [FM-001](FM-001.md) with `"patterns": { "title": ".+" }`. `titleKey` takes the same dot-separated path as FM-001, so `meta.title` finds `title` nested under `meta`.

A front matter title does not count toward `singleTitle`. A document with `title:` in its front matter and one `# Title` heading passes. (markdownlint's MD025 counts the front matter title as a top-level heading; SEC-004 does not.)

If the front matter is not valid YAML, or is not a mapping, SEC-004 does not report the YAML error, because FM-001 does. The `title` check then passes only if the document starts with a heading at `level`. If it does not, the finding's message ends with `(front matter could not be read)`, so a broken block never passes silently.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `increment` | `boolean` | no | `true` | Report a heading more than one level deeper than the one before it. |
| `singleTitle` | `boolean` | no | `true` | Report every heading at `level` after the first. |
| `title` | `boolean` | no | `true` | Require a heading at `level` as the first block, or a front matter `titleKey` key. |
| `level` | `integer` (1–6) | no | `1` | The top-level heading depth for `singleTitle` and `title`. |
| `titleKey` | `string` | no | `"title"` | Front matter key (dot path) that satisfies `title`. |
| `files` | `string[]` | no | all included | Glob(s) narrowing which files this rule instance applies to. |
| `exclude` | `string[]` | no | — | Glob(s) removing files from this rule instance. |

## Example

### Config

```jsonc
{
  "rules": [{ "rule": "SEC-004" }],
}
```

### Passes

```md
---
title: Release process
---

## Prepare

### Checklist

## Publish
```

The front matter title satisfies `title`, there is no H1 at all, and every heading is at most one level deeper than the one before it.

### Fails

```md
Some intro text.

# Guide

## Setup

#### Details

# Appendix
```

→ SEC-004 reports three findings: line 1, because the document starts with prose rather than an H1 heading or a front matter `title`; line 7, because the heading level skips from H2 to H4; and line 9, because there is more than one H1 heading.

### A changelog with one heading per release

```jsonc
{
  "rule": "SEC-004",
  "options": { "singleTitle": false, "files": ["CHANGELOG.md"] },
}
```

`increment` and `title` still apply; only the repeated top-level headings are allowed.

## Notes

- **Scope:** `document` — evaluated per file, independent of other files.
- **Not fixable:** choosing the right level for a heading is a judgment call, so SEC-004 reports rather than rewrites.
- **Default severity is `warning`:** these are outline-hygiene checks, and the rule is meant to be enabled without options.
- A finding can be silenced with an inline `<!-- wastech-mdlint-disable-next-line SEC-004 -->`. The directive is a comment, so it is not counted as the first block.
