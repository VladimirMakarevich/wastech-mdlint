# CTX-006 — Fenced code blocks declare a language

> Category **CTX** (content quality) · Scope **document** · Default severity **warning** · Fixable **no** · Alias **`code-block-language`** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

CTX-006 reports a fenced code block whose opening fence names no language. The language word after the fence tells a model whether the block is a command to run, a config to write or output to compare against; a bare fence leaves it guessing.

- **Fences with ` ``` ` and `~~~`** are both checked, wherever they appear: at the top level, indented by up to three spaces, inside a blockquote or a list item. A fence that is never closed is still a fence.
- **The language** is the first word of the info string, so ` ```js title="a.js" ` has the language `js`. An info string made only of whitespace counts as none.
- **The finding** is placed at the opening fence's line and column.

With the `allowed` option, a fence whose language is not in the list is reported too. The comparison ignores letter case, so `BASH` matches an allowed `bash`. A fence with no language is reported with the missing-language message whether or not `allowed` is set.

What CTX-006 does not check:

- **Indented code blocks** (four spaces or a tab). They have no info string, so they cannot carry a language.
- **Inline code** and **raw HTML `<pre>`** blocks.
- **Whether the language is real.** Any word passes without `allowed`, and the info string is not interpreted: ` ```{.python} ` has the language `{.python}`, not `python`.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `allowed` | `string[]` | no | any language | Languages a fence may declare, compared ignoring letter case. Each entry is one word with no whitespace; the list must not be empty. |
| `files` | `string[]` | no | all included | Glob(s) narrowing which files this rule instance applies to. |
| `exclude` | `string[]` | no | — | Glob(s) removing files from this rule instance. |

## Example

### Config

```jsonc
{
  "rules": [{ "rule": "CTX-006", "options": { "allowed": ["bash", "json"] } }],
}
```

### Passes

````md
```bash
npm test
```
````

### Fails

````md
```
npm test
```

```sh
npm test
```
````

→ CTX-006 reports line 1: ``Fenced code block has no language; name one after the opening fence, such as `bash`.``

→ CTX-006 reports line 5: `Fenced code block language "sh" is not in the allowed list.`

## Notes

- **Scope:** `document` — evaluated per file, independent of other files.
- **Not fixable:** choosing a language is a judgment call, so CTX-006 reports rather than rewrites.
- **Default severity is `warning`:** this is writing hygiene, and the rule is meant to be enabled without options.
- `init` does not propose CTX-006; add it to your config yourself.
- A finding can be silenced with an inline `<!-- wastech-mdlint-disable-next-line CTX-006 -->` on the line before the opening fence.
