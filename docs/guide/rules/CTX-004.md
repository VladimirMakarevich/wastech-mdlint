# CTX-004 — Descriptive link text

> Category **CTX** (content quality) · Scope **document** · Default severity **warning** · Fixable **no** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

CTX-004 reports a link whose visible text says nothing about its target, such as `[here](setup.md)` or `[подробнее](setup.md)`. An agent, like a reader scanning a page, decides whether to follow a link from its text alone, and "here" carries no information.

The link text is normalised, and so is every configured phrase, before they are compared:

1. The text is put in Unicode NFC form, so a letter written as a base letter plus a combining mark (`й` as `и` + `◌̆`) compares equal to its precomposed form.
2. Every run of whitespace, line breaks included, becomes one space. A link whose text wraps across lines (`[click` / `here](a.md)`) is compared as `click here`.
3. Punctuation, symbols and spaces are trimmed from both ends, so `here.`, `«здесь»`, `(link)` and `read more →` all match their bare phrase. Punctuation inside the text stays: `here-and-there` is not `here and there`.
4. The text is lower-cased the same way on every machine, independent of the host locale. Cyrillic is lower-cased too, so `ЗДЕСЬ` matches `здесь`.

The **whole** normalised text must equal a phrase. `[more about installation](a.md)` is not reported even though `more` is in the list.

The default list:

- English: `here`, `click here`, `click`, `link`, `this link`, `more`, `read more`, `learn more`, `this`, `this page`
- Russian: `здесь`, `тут`, `сюда`, `ссылка`, `по ссылке`, `эта ссылка`, `подробнее`, `читать далее`, `нажмите здесь`

### What counts as link text

Only the link's own text decides; its target never does.

- **Inline and reference links** are judged alike: `[here](a.md)`, `[here][ref]` and a shortcut `[here]` with a matching definition are all reported. A reference whose label has no definition is not a link at all; [REF-007](REF-007.md) reports it.
- **Inline code** counts as text, so ``[`here`](a.md)`` is reported.
- **Inline HTML** is markup, not text: the tags are left out and the text between them is judged, so `[<em>here</em>](a.md)` is reported as `here`. An inline `<br>` in any spelling (`<br/>`, `<BR />`, `<br class="x">`, or the stray end tag `</br>`) renders a line break, so it counts as a space: `[click<br>here](a.md)` is judged as `click here`. A label that is only tags (`[<b></b>](a.md)`) has no text.
- **Autolinks** (`<https://example.com>`, `<user@example.com>`, a bare `www.example.com`) and links whose text is the URL itself (`[https://example.com](https://example.com)`) are judged by that text like any other link. The text is the target, which names it exactly, and no default phrase is a URL, so with the default list they are never reported. A URL you add to `phrases` or `additionalPhrases` is matched like any other phrase.
- **Image links** are judged by the text beside the image, not by the image's alt text. `[![here](button.png)](a.md)` has no text and is not reported; `[![icon](i.png) here](a.md)` has the text `here` and is reported. A standalone image `![here](x.png)` is not a link. Alt text describes an image, which is a different check.
- **Empty text** (`[](a.md)`) and text that is only punctuation (`[→](a.md)`) are not reported: no phrase can match them. [REF-008](REF-008.md) covers links with no target.

Links are checked wherever they appear: in paragraphs, headings, list items and table cells.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `phrases` | `string[]` | no | the default list above | **Replaces** the default list. At least one entry. |
| `additionalPhrases` | `string[]` | no | — | **Extends** the list in effect: the defaults, or `phrases` when given. |
| `files` | `string[]` | no | all included | Glob(s) narrowing which files this rule instance applies to. |
| `exclude` | `string[]` | no | — | Glob(s) removing files from this rule instance. |

Phrases are normalised the same way as link text, so `"Click Here!"` in config matches `[click here](a.md)`. Every phrase must contain at least one letter or digit: a phrase made only of punctuation would normalise to nothing and never match, so the config is rejected when it loads.

Unlike [CTX-001](CTX-001.md)'s `placeholders`, which can only add to its defaults, CTX-004 can also replace them, so a project writing in another language can drop the English and Russian list.

## Example

### Config

```jsonc
{
  "rules": [
    {
      "rule": "CTX-004",
      "options": { "additionalPhrases": ["see", "docs"] },
    },
  ],
}
```

### Passes

```md
Read the [installation guide](install.md) before you start.

Releases are listed at <https://example.com/releases>.
```

### Fails

```md
For setup steps, click [here](install.md).
```

→ CTX-004 reports line 1: `Link text "here" does not describe its target; name what the link leads to.`

## Notes

- **Scope:** `document` — evaluated per file, independent of other files.
- **Not fixable:** choosing descriptive text is a judgment call, so CTX-004 reports rather than rewrites.
- **Default severity is `warning`:** this is writing hygiene, and the rule is meant to be enabled without options.
- A finding can be silenced with an inline `<!-- wastech-mdlint-disable-next-line CTX-004 -->` on the line before the link.
