# REF-009 — Link reference definitions are used

> Category **REF** (references) · Scope **document** · Default severity **warning** · Fixable **yes** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

Every link reference definition — a `[label]: target` line — must be used by at least one reference-style link or image in the same file. REF-009 reports each definition whose label no full (`[text][label]`), collapsed (`[label][]`) or shortcut (`[label]`) reference uses, anchored at the definition's opening `[`.

A definition renders nothing on the page. When the link that used it is deleted or rewritten, the definition stays behind, invisible to a reader, and its target is never checked by anyone following a link, because there is no link. REF-009 is the mirror of [REF-007](REF-007.md): REF-007 reports a reference with no definition, REF-009 a definition with no reference.

Labels match the way CommonMark matches them: case-insensitively, with runs of whitespace treated as one space, so `[Setup Guide]: …` is used by `[read this][setup   guide]`.

The label `//` is ignored by default, because `[//]: # (comment)` is the common idiom for a Markdown comment and is unused on purpose.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `ignoredDefinitions` | `string[]` | no | `["//"]` | Labels never reported, compared with the label exactly as written (case-sensitive). Setting it replaces the default, so keep `"//"` in the list if you use the comment idiom. |
| `files` | `string[]` | no | all included | Glob(s) narrowing which files this rule instance applies to. |
| `exclude` | `string[]` | no | — | Glob(s) removing files from this rule instance. |

## Example

### Config

```jsonc
{
  "rules": [{ "rule": "REF-009" }],
}
```

### Passes

```md
Read the [setup guide][setup].

[setup]: docs/setup.md
[//]: # "a Markdown comment"
```

### Fails

```md
Read the [setup guide][setup].

[setup]: docs/setup.md
[old-setup]: docs/legacy/setup.md
```

→ REF-009 reports one finding on line 4, column 1: `Reference definition "[old-setup]" is not used by any reference link or image in this document; remove it or link to it.` The finding's `data` carries `label`.

## Fix

`lint --fix` deletes each unused definition together with the line(s) it occupies, including the line ending, so no blank line is left where it was. When the definition is the last line of a file that does not end with a line ending, the line ending before it is removed instead, so the file does not gain a trailing blank line. Adjacent unused definitions are removed in one pass. Nothing else in the file changes: blank lines around the definition stay, and CRLF line endings stay CRLF.

A definition is reported but **not** fixed when it does not own its lines: one inside a blockquote or list item (deleting the line would delete the `>` or list marker with it), or one sharing a line with other text.

A second `--fix` run changes nothing: a deleted definition can no longer be reported.

## Notes

- **Scope:** `document` — a definition can only be used from the file it is in, as Markdown requires.
- **Not REF-005.** [REF-005](REF-005.md) checks ID traceability between table rows and headings; its "definitions" are content, not link reference definitions, and are never deleted.
- **Duplicate labels** are judged by label: when a label is used, every definition of it counts as used, and none is reported. Which duplicate is the dead one depends on which one Markdown resolves, so this rule leaves duplicates to the author.
- **Never read:** definitions shown inside code spans, fenced or indented code blocks, HTML or front matter are not definitions at all.
- **Not proposed by `init`.** A corpus can only show evidence for this rule by containing an unused definition, which is itself a finding, so `init` never adds it to a draft config. Enable it by hand.
- **`files`/`exclude`** narrow which files this rule instance applies to, for the check and for `--fix` alike.
