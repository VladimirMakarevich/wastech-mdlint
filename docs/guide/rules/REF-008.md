# REF-008 — Links and images have a target and use link syntax in the right order

> Category **REF** (references) · Scope **document** · Default severity **error** · Fixable **no** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

REF-008 reports two mistakes that every other link rule lets through.

**Empty targets.** A link or image whose target is empty — `[text]()`, `[text](<>)`, `![alt]()` — or a bare fragment — `[text](#)` — is reported at its opening `[` (or at the `!` of an image). Markdown renders such a link, but it goes nowhere (a bare `#` only jumps to the top of the page), and an image shows nothing. [REF-001](REF-001.md), [REF-002](REF-002.md) and [REF-003](REF-003.md) skip these targets because there is nothing to resolve, so without REF-008 a dead link passes every check. A reference whose definition is empty (`[text][d]` with `[d]: <>`) is the same dead link and is reported the same way. Only a bare `#` counts: `[text](#top)` and `[text](./a.md#)` have something to resolve and are left to REF-001 and REF-002.

**Reversed link syntax.** `(text)[https://example.com]` and `(text)[./a.md]` are link syntax written in the wrong order. Markdown does not recognise them as links, so they render as the literal parentheses and brackets. REF-008 reports each one at its opening `(`, quoting what was written and the corrected form.

## Example

### Config

```jsonc
{
  "rules": [{ "rule": "REF-008" }],
}
```

### Passes

```md
See [the guide](docs/guide.md) and [back to top](#top).

![diagram](images/diagram.png)

Read [the docs](https://example.com) first (see below) [1].
```

### Fails

```md
See [the guide]() and [back to top](#).

![diagram]()

Read (the docs)[https://example.com] first.
```

→ REF-008 reports four findings:

- line 1, column 5: `Link "[the guide]" has an empty target, so it goes nowhere; add a target or remove the link.`
- line 1, column 23: `Link "[back to top]" has a bare "#" target, so it only jumps to the top of the page; add a target or remove the link.`
- line 3, column 1: `Image has an empty target, so no image is shown; add a target or remove the image.`
- line 5, column 6: `"(the docs)[https://example.com]" is reversed link syntax and renders as literal text; write it as "[the docs](https://example.com)".`

Each finding's `data` carries `problem`. An empty-target finding (`problem: "empty-target"`) also carries `kind` (`link` or `image`) and `target` (`""` or `"#"`); a reversed-syntax finding (`problem: "reversed"`) carries `text` and `target` as written.

## Notes

- **Scope:** `document` — evaluated per file.
- **Never read:** code spans, fenced and indented code blocks, inline and block HTML, frontmatter, and the content of inline HTML elements whose text is shown literally (`<code>`, `<kbd>`, `<samp>`, `<tt>`, `<pre>`, and raw-text elements such as `<script>`, `<style>` and `<textarea>`); text inside ordinary elements such as `<b>` or `<span>` is prose and is read. Parentheses or brackets written with escapes (`\(`, `\[`) or HTML entities (`&#40;`) are not link syntax either.
- **Only target-like brackets are reversed links.** Bracketed prose right after a parenthetical is common, so the bracket content must look like a link target before anything is reported: it starts with a URI scheme (`https:`, `mailto:`), `/`, `./`, `../`, `#` or `www.`, contains a `/`, or ends in a file extension such as `.md` (optionally followed by a `#fragment`). `(see below)[1]` and `(sic)[WIP]` are never reported, and neither is `(see below) [1]`, where a space separates the two. A bracket holding whitespace is never a target.
- **A defined reference is not reversed.** In `(see the guide)[guide]` with a `[guide]: …` definition, the brackets are a real shortcut reference link that follows a parenthetical, so nothing is reported. The same goes for `(note)[x](u)` and `(note)[x][d]`, which are an inline link and a full reference after a parenthetical.
- **Overlap with REF-007.** With [REF-007](REF-007.md)'s `includeShortcut: true`, the brackets of `(text)[./a.md]` are also an undefined shortcut reference, so both rules report it. The two findings describe different problems, so neither rule suppresses the other.
- **Not fixable.** A missing target cannot be invented, and turning a parenthetical into a link is a judgement call, so the repair is left to the author.
- **No graph edge.** An empty target points nowhere and a reversed target is unrendered text, so neither adds anything to the context graph.
- **Not proposed by `init`.** A corpus can only show evidence for this rule by containing an empty target or a reversed link, which is itself a finding, so `init` never adds it to a draft config. Enable it by hand.
- **`files`/`exclude`** narrow which files this rule instance applies to.
