# SEC-003 — Sections conform to a template

> Category **SEC** (sections) · Scope **project** · Default severity **error** · Fixable **no** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

Files in scope must carry every section heading that a reference **template** file declares. SEC-003 reads the template named by `template`, collects its heading texts, and reports — for each in-scope file — every template heading that the file is missing.

This checks a whole family of documents against one canonical outline: point `template` at a `template.md` and every ADR, RFC, or runbook must reproduce its section headings. Unlike [SEC-001](SEC-001.md), where you list the required sections inline, SEC-003 derives them from a real file so the outline lives in one editable place.

By default order is **not** enforced — only presence of each template heading; use [SEC-002](SEC-002.md) for order, or set `strict` to check the whole outline (see [Strict outline mode](#strict-outline-mode)). The template file itself is never checked against its own headings. Set `level` to compare only headings at one depth (e.g. `2` compares only `##` headings). A file's own missing section is reported at line 0 of that file.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `template` | `string` | **yes** | — | Repo-relative path to the reference file whose headings define the outline. |
| `level` | `integer` (≥1) | no | all depths | Only require template headings at this depth (e.g. `2` = `##`). |
| `strict` | `boolean` | no | `false` | Require the file's heading sequence to match the template's exactly — presence, order, depth and no extra headings — with `*`, `+` and `?` template headings as wildcards. |
| `files` | `string[]` | no | all included | Glob(s) narrowing which files are checked against the template. |
| `exclude` | `string[]` | no | — | Glob(s) removing files from this rule instance. |

## Example

### Config

```jsonc
{
  "rules": [
    {
      "rule": "SEC-003",
      "options": {
        "template": "template.md",
        "files": ["adr/**/*.md"],
        "level": 2,
      },
    },
  ],
}
```

### Template (`template.md`)

```md
# T

## Context

## Decision
```

### Passes (`adr/two.md`)

```md
# Two

## Context

## Decision
```

### Fails (`adr/one.md`)

```md
# One

## Context
```

→ SEC-003 reports that `adr/one.md` is missing section **`Decision`**, which is required by template `template.md`.

## Strict outline mode

With `strict: true`, SEC-003 compares each file's full heading sequence against the template's, in one rule: every template heading must be present, in the template's order, and the file may not add headings the template does not account for.

- **Literal headings** match one heading with the same text (case-sensitive) **and** the same depth: a template `## Context` is not satisfied by `### Context`.
- **Wildcard headings** are template headings whose whole text is `*`, `+` or `?`:
  - `?` matches exactly one heading;
  - `*` matches zero or more headings;
  - `+` matches one or more headings.

  A wildcard matches headings at its own depth **or deeper**, so `## *` absorbs an extra `## Options` section together with its `### …` subsections, but never a shallower heading such as `# Title`. Wildcards count headings, not sections: `## ?` is also satisfied by a single `### Note`.

- **`level`** keeps its exact-depth meaning and filters both sides: with `level: 2`, only `##` headings of the template and of each file take part, so a per-document `# Title` may differ.
- **One finding per file**, at the first point where the file departs from the template. The message names the expected template heading (with its template line) and the heading actually found, e.g. `Outline diverges from template template.md: expected "## Decision" (template line 5), found "## Extra".` The finding sits on the found heading's line. When the file ends while the template still requires a heading, it reads `found end of document` and sits at line 0; when the template is complete but the file has another heading, it reads `expected no further heading`. The finding's `data` carries `template`, `expected` and `actual`, each `expected`/`actual` being `{ text, depth, line }` or `null` for those two boundary cases.
- Wildcards only have meaning under `strict`. Without it, a `## *` template heading is an ordinary required section named `*`.
- There is no way to write a literal `*`, `+` or `?` heading in a strict template: the Markdown parser reads `## \*` as the text `*`, so an escaped asterisk is still a wildcard.

### Strict config

```jsonc
{
  "rules": [
    {
      "rule": "SEC-003",
      "options": {
        "template": "template.md",
        "files": ["adr/**/*.md"],
        "strict": true,
      },
    },
  ],
}
```

### Strict template (`template.md`)

```md
# ?

## Context

## \*

## Decision
```

### Passes (`adr/two.md`)

```md
# Use PostgreSQL

## Context

## Options

### Managed

## Decision
```

### Fails (`adr/one.md`)

```md
# Use Redis

## Decision

## Context
```

→ SEC-003 reports one finding on `adr/one.md` line 3: `expected "## Context" (template line 3), found "## Decision"`.

## Notes

- **Scope:** `project` — the template is loaded once and every in-scope file is compared against it.
- **Missing template:** if `template` cannot be read, SEC-003 emits a single config-attributed error (`… was not found; skipping conformance checks.`) and performs no per-file checks, so a mistyped path never produces a flood of false positives.
- **Path containment:** `template` reaches the filesystem with a path you supply (as does [STR-001](STR-001.md)'s `files`), so it is held to the analyzed root: a relative path whose `..` segments climb outside the root — or _any_ absolute path, including one that happens to point back inside the root — is rejected with a config-attributed error (`… escapes the analyzed root; skipping conformance checks.`). Write the path repo-relative and this never fires. The check runs **before** the file is touched, so a rejected path cannot be distinguished from a nonexistent one: that is deliberate, because "was not found" on an out-of-root path would itself report whether an arbitrary file exists on the host. Containment is lexical — a symlink that lives inside the root but points outside it is still followed.
- **Not fixable:** template conformance may need bodies as well as headings, so SEC-003 reports rather than rewrites. For an inline required-section list with a `--fix` scaffold, use [SEC-001](SEC-001.md).
- With `level` set, only template headings at that exact depth are required; a file need not reproduce the template's `# Title`.
