# REF-002 — Link anchors match a heading or HTML anchor

> Category **REF** (references) · Scope **document** · Default severity **error** · Fixable **no** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

Every link anchor in scope must resolve in the file it points at. REF-002 reads each link's `#anchor` fragment and reports a finding when the target file declares no such anchor.

A fragment resolves when it is one of:

- **A heading slug.** Slugs are computed with `github-slugger`, so `## Getting Started` produces `getting-started`. A repeated heading gets `-1`, `-2`, … in document order.
- **An HTML anchor.** An `id` attribute on any element (`<a id="custom"></a>`, `<div id="custom">`), or a `name` attribute on an `<a>` element (`<a name="custom"></a>`). `name` on any other element is not a fragment target and is ignored. The attribute value is compared exactly as written. As in HTML, only the first `id` (and the first `name`) on a tag counts, so `<a id="one" id="two">` declares `one` alone. HTML inside inline code, a fenced code block, an HTML comment or frontmatter is not read, and neither is anything inside an element whose content a browser treats as text: `<script>`, `<style>`, `<textarea>`, `<title>`, `<iframe>`, `<xmp>`, `<noembed>` and `<noframes>`. An `id` on that element's own tag still counts.
- **`#top`.** It always resolves, in any letter case, because a browser scrolls a `#top` link to the start of the page even with no element of that name.
- **A GitHub line fragment.** `#L5` (a line), `#L5C3` (a line and column), `#L10-L12` (a range) and `#L10C5-L12C3` (a range with columns). Lines and columns start at 1 and the `L` and `C` are uppercase, so `#L`, `#Lx`, `#L0` and `#l5` are reported. The line numbers are not checked against the length of the target file.

Two anchor forms are handled:

- **Same-file anchors** (`[jump](#getting-started)`) are validated against the linking document itself.
- **Cross-file anchors** (`[jump](guide.md#getting-started)`) are validated against the resolved target file.

If a cross-file target file cannot be resolved, REF-002 skips it — a missing target file is [REF-001](REF-001.md)'s concern, not this rule's. Links without an anchor are ignored, and only same-file and local-file links participate; other schemes are skipped. This is a **local-only** check with no network access.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `ignoreCase` | `boolean` | no | `false` | Compare the fragment with heading slugs and HTML anchors case-insensitively, so `#Demo` matches `# Demo`. Off by default because GitHub matches fragments case-sensitively. `#top` is case-insensitive either way; line fragments stay case-sensitive either way. |
| `ignoredPattern` | `string` (regex) | no | — | A regular expression tested against the fragment (decoded, without the `#`). A matching fragment is never reported. The pattern is unanchored — write `^…$` to match the whole fragment — and compiled without flags; `ignoreCase` does not apply to it. A pattern that does not compile is a config error at load time, naming `config.rules[i].options.ignoredPattern`. |
| `siteRouter` | `object` | no | inherits `settings.siteRouter` | Overrides the site router used to resolve cross-file targets for this rule instance. See [Site router](#site-router). |
| `files` | `string[]` | no | all included | Glob(s) narrowing which files this rule instance applies to. |
| `exclude` | `string[]` | no | — | Glob(s) removing files from this rule instance. |

The `siteRouter` object accepts `preset`, `contentDir`, and `defaultLocale` (all optional strings).

## Example

### Config

```jsonc
{
  "rules": [{ "rule": "REF-002" }],
}
```

### Passes

```md
## Intro

<a id="details"></a>

Jump to the [intro](#intro), the [details](#details), the [top](#top), or the [overview](b.md#overview).
```

with `b.md`:

```md
## Overview
```

→ Every anchor resolves, so REF-002 reports nothing.

### Fails

```md
## Intro

Jump to the [missing section](#nope), the [Intro](#Intro) or a [bad cross-link](b.md#missing).
```

→ REF-002 reports that anchor **`#nope` does not match any heading or HTML anchor** in the current file, the same for `#Intro` (the slug is `intro`), and that anchor **`#missing` does not match any heading or HTML anchor** in `b.md`.

With `"options": { "ignoreCase": true }`, `#Intro` is accepted and only `#nope` and `#missing` are reported. With `"options": { "ignoredPattern": "^miss" }`, `#missing` is skipped instead.

## Site router

`settings.siteRouter` is **inherited by reference rules** and drives how root-relative cross-file targets are resolved to source files before their anchors are read; a per-rule `siteRouter` option overrides the inherited value for that instance. See [REF-001](REF-001.md#site-router) for the mapping details and locale fallback.

## Notes

- **Scope:** `document` — evaluated per file, but cross-file anchors consult the resolved target's headings and HTML anchors from the corpus.
- **Agreement with the context graph.** For a link to another file, the [context graph](../context-graph.md) builds an `anchor` edge exactly when REF-002, under its default options, accepts the fragment, and `slice "#x"` starts from the files declaring `x` as a heading slug or HTML anchor. `#top` and line fragments resolve in every file, so `slice` does not match them at all rather than starting from the whole corpus. `ignoreCase` and `ignoredPattern` apply to this rule instance only: the graph takes no rule options, so a fragment accepted only because of them produces no `anchor` edge.
- HTML anchors are found by a small attribute scan, not a full HTML parser. Text inside a quoted attribute value is never read as an attribute or a tag, so `<div title="see id='x'">` declares no `x`. An unterminated quote is the exception: the text after it is scanned as markup.
- Unresolvable target files are skipped so REF-002 and [REF-001](REF-001.md) do not both report the same broken link.
