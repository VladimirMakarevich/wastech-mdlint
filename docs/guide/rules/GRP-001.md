# GRP-001 — No circular references

> Category **GRP** (graph integrity) · Scope **project** · Default severity **error** · Fixable **no** · [Rules index](README.md) · [Configuration](../configuration.md)

## What it checks

Documents in the repository must not form a **dependency cycle**. GRP-001 reads the shared [ContextGraph](../context-graph.md) and reports a finding for each cycle the graph reports — a chain of documents where following references leads back to where it started (e.g. `a.md → b.md → c.md → a.md`).

Cycles are computed once, corpus-wide, from the graph's edges. Every kind of reference edge counts: plain Markdown links, in-page anchor links, image references, and eager `@import` directives. When [`settings.idRef`](../configuration.md) is configured, `id-ref` edges (a document that mentions an ID defined in another document) also participate, so an ID reference can close a cycle just like a link does.

Because this rule reasons about relationships _between_ files, its scope is `project`: it runs once over the whole corpus rather than per file. The finding is attributed to the first document in the cycle, anchored at the line of the first arc (the edge leaving that document); if the arc has no known line, it anchors at the top of the file.

## Options

| Option | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `minCycleLength` | `integer` (≥2) | no | `3` | How many distinct documents a cycle must span before it is reported. |

**`minCycleLength` defaults to `3`, so a two-document mutual link is not reported.** A README that indexes its siblings while a sibling links back is an ordinary documentation shape, not a defect — and at this rule's `error` severity it would fail the build, whose likely answer is switching GRP-001 off entirely and losing the longer cycles it also finds. Set `"minCycleLength": 2` to report mutual links as well. Note that a mutual **eager import** (`@a.md` ↔ `@b.md`) is a genuine problem and is reported by [LLM-001](LLM-001.md) regardless of this option.

> **On exactness:** the graph reports **one representative cycle per strongly connected component**, and that path is the first one the traversal finds, not the shortest one available. So `minCycleLength` filters the representative path's length, and a tangled component containing both a back-link and a longer loop is judged by whichever path was extracted. For the ordinary case — a component that _is_ one cycle — the length is exactly the number of documents in it.

> **Why no scoping keys:** the shared ContextGraph is built once for the whole corpus, and each rule's options are already sealed inside the rule by then — so a per-rule key could not narrow what the cycle detection sees even in principle. `files`, `exclude`, and `siteRouter` used to be accepted here and silently did nothing; they were removed so validation no longer advertises a no-op. `minCycleLength` is wireable precisely because it filters the rule's own findings afterwards rather than the graph. Route resolution comes from [`settings.siteRouter`](../configuration.md#settingssiterouter), which the graph builder reads; per-rule graph scoping would need a graph-scoping design, not a schema key. Narrow the corpus itself with the top-level `include`/`exclude` instead.

## Example

### Config

```jsonc
{
  "rules": [{ "rule": "GRP-001" }],
}
```

### Passes

```md
<!-- index.md -->

See [details](detail.md).

<!-- detail.md -->

# Detail
```

`index.md` links to `detail.md`, and `detail.md` links nowhere back — acyclic.

### Fails

```md
<!-- a.md -->

See [b](b.md).

<!-- b.md -->

See [c](c.md).

<!-- c.md -->

See [a](a.md).
```

→ GRP-001 reports **`Dependency cycle detected: a.md -> b.md -> c.md -> a.md.`**, anchored at the link in `a.md`.

### Cycle closed by ID references

With `settings.idRef` enabled, prose that mentions another document's ID forms an `id-ref` edge. This example is a two-document cycle, so it also needs `minCycleLength: 2` to be reported:

```jsonc
{
  "settings": {
    "idRef": {
      "idPattern": "^REQ-\\d+$",
      "definitions": ["*.md"],
      "idColumn": "ID",
    },
  },
  "rules": [{ "rule": "GRP-001", "options": { "minCycleLength": 2 } }],
}
```

```md
<!-- a.md -->

| ID    |
| ----- |
| REQ-1 |

See REQ-2 for context.

<!-- b.md -->

| ID    |
| ----- |
| REQ-2 |

See REQ-1 for context.
```

→ GRP-001 reports the cycle **`a.md -> b.md -> a.md.`** — the two ID references close the loop. Without `settings.idRef`, no `id-ref` edges are built and there is no cycle to report.

## Notes

- **Scope:** `project` — evaluated once over the whole corpus, not per file.
- **Edges considered:** links, anchors, images, `@import`, and `id-ref` (the last only when `settings.idRef` is set). See [Context graph](../context-graph.md).
- **Attribution:** one finding per cycle, on the first document in the cycle at the first arc's line.
- **Two-document cycles are silent by default.** See `minCycleLength` above. The [`graph`](../context-graph.md) command still counts every cycle the graph found (and the `context_graph` MCP tool still returns them all), because those surfaces report the graph rather than this rule.
