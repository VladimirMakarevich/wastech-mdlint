# P13.02 · A lint-time default `exclude`

> Phase: [P13 — Correctness](index.md) · Roadmap: [v2 Index](../index.md) · Size **S–M** · Status **Done**. Backlog: [W-02](../remediation-backlog-2026-08-05.md) (Blocker). Sources: field F-06 (blocker; the symptom was independently reproduced by audit F25 and mis-graded LOW there). Depends on [P13.01](01-glob-semantics.md).

## Goal

Make the zero-config first run — `npx wastech-mdlint lint .`, the path a new user takes before reading anything — prune the directories no Markdown analyzer should read. Today it prunes nothing.

## Problem

[`packages/core/src/markdown/load-documents.ts`](../../../packages/core/src/markdown/load-documents.ts) around `:147` reads `exclude: options.exclude ?? []`. There is no lint-time default. The only `node_modules` literals in `core/src` live in `discovery/repo-scan-constants.ts` (the `init` scan's noise list) and `discovery/config-writer.ts` (what `init` writes) — **both `init`-only** — so a user who never runs `init` gets no pruning whatsoever. The schema declares no `default` for `exclude` or `respectGitignore` either, so an editor cannot show one.

**Measured on a real monorepo (202 tracked `.md`, 323 excluding `node_modules`):** 3063 files instead of 323, of which 2740 sat under a **nested** `mobile/node_modules/`; 19.30 MB parsed instead of ~1.9 MB; 31 s wall instead of 2 s. Exit `0`, zero findings — because the zero-config ruleset is empty, so the blow-up is silent in every direction. The same run after `init` took 2 s over 139 files, which is the cost of this defect measured directly.

**Why the audit reproduced it and did not file it.** Audit F25's own verification pulled `node_modules/pkg/README.md` into the corpus and filed that as a LOW documentation gap about pattern anchoring. It never asked why `node_modules` was a candidate at all — because its method asks whether code contradicts a documented claim, and no document promises a default `exclude`. The field test's plan _expected_ the pruning, and that expectation is what turned a passing observation into a blocker.

## Deliverables / steps

1. **Ship a lint-time default `exclude`.** At minimum the any-depth set `init` already writes for the same reason: `**/node_modules/**`, `**/dist/**`, `**/build/**`, `**/.git/**`. Prefer reusing the constant behind `discovery/config-writer.ts` rather than introducing a second list — two lists that must agree is the shape of the next drift.
2. **Anchoring matters here.** Write the defaults in the depth-agnostic form, per [P13.01](01-glob-semantics.md)'s rule; a root-anchored `node_modules/**` default would reproduce the field test's F-07 under-exclusion inside the product itself.
3. **Declare the default in the generated schema** so an editor surfaces it, and regenerate `packages/cli/schema.json` plus any README table in the same change (the byte-sync tests will otherwise fail).
4. **Decide `respectGitignore` separately, and land it after [P13.03](03-gitignore-precedence.md).** Its default is `false` today. Whether it should become `true` is a distinct question — a repository's `.gitignore` is not the same statement as "do not lint this" — so either change it deliberately with a note, or leave it and say so. **Sequencing is load-bearing here:** until P13.03 fixes the root-first-wins layer precedence (W-11), a nested `!keep.md` cannot re-include a file a root pattern ignored, so a `true` default would put that silent under-reporting on the zero-config path — the same failure class this task exists to close, arriving through the fix. Ship the `exclude` default whenever; flip `respectGitignore` only once P13.03 has landed, and if the two are done in one pass, say so in the change. Whichever way it is decided, declare the resolved default in the generated schema alongside `exclude` (step 3) so neither key is invisible to an editor.
5. **Add the boundary guard.** A three-file fixture with **no config**: `docs/a.md`, `mobile/node_modules/leftpad/README.md`, `node_modules/rightpad/README.md`. It must lint exactly one file. Tag it `@boundary-guard shared-exclude` so [`packages/core/test/boundary-guards.test.ts`](../../../packages/core/test/boundary-guards.test.ts) holds the pairing — the nested copy is the half an in-repo fixture has never had.
6. **Fix the two stale plan numbers this created.** [`field-test-2026-08-05-debates.md`](../field-test-2026-08-05-debates.md) Phase 3 expects 323 files and asserts that `node_modules` is excluded by default. After this task that expectation becomes correct; update the plan so the number reads as a passing check rather than a known-wrong one.
7. **Update the guide.** `docs/guide/configuration.md` should state what is excluded before the user writes anything, and that a user-supplied `exclude` replaces rather than extends it (or extends it — decide, and say which).

## Out of scope

Performance work on the parse path. The 31 s was 3063 files, not a slow parser; pruning is the fix. Also out of scope: making `init`'s written `exclude` and the lint-time default diverge — if they must differ, that belongs in [P14.03](../P14-host-boundary/03-init-disclosure.md), which owns the `init`-vs-lint distinction.

- [x] Gates green.

## Implementation notes

- **A user `exclude` extends the default; it does not replace it.** The effective list is `[...DEFAULT_EXCLUDE_GLOBS, ...(config.exclude ?? [])]`, deduped by first occurrence. _Replace_ was rejected because it leaves the blocker open for exactly the users who engage with the key: `"exclude": ["drafts/**"]` is an ordinary first edit, and under replace it silently re-opens every `node_modules` tree while still exiting `0` with a plausible file count — W-02 all over again, in the one config that looks like it took care of the problem. Under extend the blocker cannot come back and the escape hatch already exists, because [P13.01](01-glob-semantics.md) made the list ordered: a user entry lands after the defaults, so `"!**/vendor/**"` un-excludes one tree and `"!**"` disables the default wholesale. The cost is real and is documented rather than hidden — **deleting a default entry from your config has no effect**, and `"exclude": []` is not an opt-out. Default-first ordering is what makes negation work at all; the dedupe is what keeps an `init`-written config (whose `exclude` _is_ this list) resolving to 11 patterns rather than 22. This is also the answer [P14.03](../P14-host-boundary/03-init-disclosure.md) asked this task for.
- **`respectGitignore` stays `false`,** with `"default": false` now declared in the schema (deliverable 4 wants the declaration either way). [P13.03](03-gitignore-precedence.md) had landed, so `true` was permitted by sequencing and was still declined: a `.gitignore` is a commit-time statement, not a lint-time one (C8 defines the key as opt-in); the measured blow-up is fully closed by the `exclude` default alone; flipping it would add a _second_ silent corpus-shrink mechanism to the zero-config path days after P13.03 changed layer precedence; and the Phase 3 expectation this task had to make pass says in as many words that `.gitignore` is not honored by default. `init` keeps writing an explicit `true`. Both defaults are handled in this one pass.
- **One list, and the contradiction it creates is surfaced rather than guessed.** Deliverable 1 says to reuse the constant behind `config-writer.ts`, the out-of-scope list forbids diverging from what `init` writes, and the constraints forbid a second list — so the lint-time default is the _full_ 11-glob list, `**/.*/**` included. That contradicts deliverable 6's field-test lines, which assumed a `node_modules`-only default (`323`, and "vendored Markdown under build directories should appear"). Resolution: ship the full list, the only option compatible with two explicit constraints, and rewrite Phase 3 so its expectation is a formula (323 minus any Markdown under a default-excluded tree) with a **count-independent** check as the load-bearing assertion — no `files[]` entry may carry a default-excluded directory segment. The consequence is flagged, not buried: on the field-test target and in this repository, dot-directory Markdown (`.github/`, `.agents/`, `.claude/`) is now outside a zero-config run — 31% of that target's tracked corpus. Whether a hidden-directory glob belongs in a lint-time default is W-15's question and stays with P14.03; W-14's disclosure gap now shows up with no config at all, not only after `init`. **Superseded by [P14.03](../P14-host-boundary/03-init-disclosure.md):** it answered W-15 with **no** — `**/.*/**` is gone from the default, `.venv`/`.yarn` were added to the noise names in its place (12 globs), and dot-directory Markdown is back inside a zero-config run. The one-list constraint still holds; the list is simply narrower.
- **The default lives in the config layer, not in `loadDocuments`.** New `packages/core/src/config/corpus-scope.ts` owns `DEFAULT_EXCLUDE_GLOBS` (moved from `config-writer.ts`, which now imports it), `DEFAULT_INCLUDE_GLOBS`, `DEFAULT_RESPECT_GITIGNORE`, and `resolveCorpusScope`; the three corpus entry points (`engine/lint-files.ts`, `engine/fix.ts`, `graph/load-context.ts`) call it, and `loadDocuments` keeps `?? []`. Putting it in the loader would have broken the one oracle that keeps gitignore behavior honest: `test/gitignore-layers.test.ts` passes an explicit `exclude` and compares the corpus against real `git ls-files`, so a loader that silently added 11 patterns would make the two sides describe different trees. `loadDocuments` is also public API whose contract is "what you pass is what I walk". The helper absorbs the `include ?? ["**/*.md"]` those three sites triplicated, and returns fresh arrays so nothing downstream can mutate the shared constant.
- **The escape hatch works at directory granularity only, and the tests say so.** `shouldPruneDirectory` probes `<dir>/__directory_probe__` before descending, so `"!**/build/**"` re-includes the tree (verified against both the plain path and the probe form) while `"!**/vendor/keep.md"` cannot rescue one file from a pruned parent — the limitation [P13.01](01-glob-semantics.md) accepted, now pinned in `corpus-scope.test.ts` so the guide's advice and the behavior stay one thing.
- **Verified red before the fix.** The core corpus case and the CLI guard both fail against the unwired resolver, with the two `node_modules` paths in the corpus. `packages/core/test/load-documents.test.ts` needed **no** edits to its existing cases — including the `build/out.md` one — which is the check that the default landed in the right layer; it gained one pin that the loader applies no default of its own. The guard lives in `packages/cli/test/lint.e2e.test.ts` with `@boundary-guard shared-exclude`, and `boundary-guards.test.ts` now lists that file under the category.
- **Two register rows.** The `init`-only noise-glob row is restated as the _lint-time_ default (every run, not only after `init`), citing P11.08 and this task and naming W-15/P14.03 as the owner of the hidden-directory question; a second row records the extend semantics and its cost. Nothing in `requirements/` changed — C1 states no default and C8 already says `false`, both still true.
- **Costs accepted, not addressed.** `matchesConfigGlob` compiles its patterns per call, so per-file and per-directory work rises by 11 patterns; net cost is strongly negative (the walk stops at the 2740 files it used to parse) and matcher caching stays out of scope. One benign side effect: `compile`'s own `.claude/skills/…/SKILL.md` output no longer re-enters the corpus on a second run — **reversed by [P14.03](../P14-host-boundary/03-init-disclosure.md)**, which dropped the hidden-directory glob; it is now a row in the [accepted behaviors register](../accepted-behaviors.md).
