# Accepted behaviors register

> Roadmap: [v2 Index](index.md) · Reference (not a precedence tier) · Established by [P12.06](P12-consistency/06-process-boundary-tests.md), deliverable 4.

The P11 remediation round fixed most of what the [post-P9 audit](audit-2026-07-25-post-p9.md) found, but some behaviors were deliberately **documented rather than changed**, and a few residuals were **recorded rather than closed**. Scattered across fifteen task files, those decisions are latent: a future reader hits the behavior, cannot tell whether it is intentional, and either "fixes" a deliberate tradeoff or files it again as a new finding.

This register is the one place they are stated. It is an **index, not a restatement**: each row points at where the behavior is already explained. Duplicating the explanation here would create a second copy to disagree with the first, so a row is a pointer plus the one-line reason it exists.

## How to use it

- **Adding a row.** When a task decides to accept a behavior instead of fixing it, add the row in the same change — the same "document where it is introduced" discipline the [glossary](glossary.md) and code comments follow.
- **User-facing vs maintainer-facing.** A behavior a _user_ can hit must have a home in `README.md` or `docs/guide/` — the register links it, it does not substitute for it. A residual only a maintainer can act on may cite its task file alone.
- **Removing a row.** When a later task actually fixes the behavior, delete the row rather than marking it stale.

## Accepted behaviors

Changing glob anchoring would silently break every existing entry rather than the narrow literal case | [STR-001](../guide/rules/STR-001.md) | [P11.12](P11-remediation/12-str001-reach.md) |
| Path containment is **lexical only**: a symlink that lives inside the analyzed root but points outside it is still probed | Resolving every candidate would add a syscall per reference on the hot path; the boundary check exists to stop the option being used as a host file-existence oracle, which lexical rejection already does | [STR-001](../guide/rules/STR-001.md) | [P11.02](P11-remediation/02-sec003-path-escape.md), [P11.12](P11-remediation/12-str001-reach.md) |

Consulting the index would mean shelling out to `git` or parsing it — neither fits a local-first matcher with no `git` dependency, and the answer would then depend on repository state rather than on the config | [Configuration](../guide/configuration.md#top-level-shape) | [P13.03](P13-correctness/03-gitignore-precedence.md) |
| `respectGitignore` patterns match **case-insensitively** on every platform, so a `README.md` pattern also skips `readme.md`, which `git` keeps on a case-sensitive filesystem | The `ignore` package's default, and pre-existing behavior that W-11 did not reach. Matching `git` would mean varying the corpus with the host filesystem's case sensitivity — the same class of host-dependence the pattern-only decision above rejects — while the current behavior is at least identical on Windows, macOS, and Linux | [Configuration](../guide/configuration.md#top-level-shape) | [P13.03](P13-correctness/03-gitignore-precedence.md) |
| Cycle detection is recursive, so one densely connected component of many thousands of documents can exhaust the call stack | Documented bound rather than a rewrite to an iterative traversal: many small components are fine at any corpus size, and no real corpus has reached it | [README limitations](../../README.md#limitations), [context graph limitations](../guide/context-graph.md#limitations) | [P12.05](P12-consistency/05-recursion-depth.md) |
| A negated `exclude` entry cannot re-include a file under a directory an earlier positive entry excludes — `["docs/private/**", "!docs/private/keepme.md"]` keeps `keepme.md` out | `shouldPruneDirectory` decides per directory before descending, so no file inside an excluded tree is ever offered to the file-level filter the negation acts on. | `GRP-001` does not report a two-document mutual link at its default `minCycleLength` of 3, so a README indexing a sibling that links back is silent unless the option is lowered to `2` | Severity, not accuracy, was the defect: at `error` an ordinary documentation shape failed the build, and the likely response is disabling the rule, forfeiting the genuine 3- and 4-hop cycles it also finds. The one dangerous two-node case — mutual eager `@import` — is reported by [`LLM-001`](../guide/rules/LLM-001.md) independently, so nothing loses its only home. `minCycleLength` also filters the _representative_ path per strongly connected component, not the component's shortest cycle | [GRP-001](../guide/rules/GRP-001.md) | [P13.04](P13-correctness/04-rule-option-defaults.md) |
| `SIZE-001`'s "at least one budget" rule is enforced only at config load, and is invisible in `packages/cli/schema.json` — an editor validating against the schema accepts `{"rule":"SIZE-001"}` that the linter then rejects | "At least one of three" has no JSON Schema-expressible shape in this generator: Zod refinements are dropped by `z.toJSONSchema`, and the alternatives are worse — marking one metric `required` would force a byte budget on a config that wants only a token one. A load-time diagnostic naming all three keys is the honest form; the previous behavior was no diagnostic at all | [SIZE-001](../guide/rules/SIZE-001.md) | [P13.04](P13-correctness/04-rule-option-defaults.md) |
| A user `GRP-002.entryPoints` **replaces** the default `["README.md", "CLAUDE.md", "AGENTS.md", "index.md"]` instead of extending it — the opposite of the top-level `exclude` row above | The asymmetry is deliberate. Dropping a default `exclude` re-opens `node_modules`, a blocker; dropping a default entry point at most re-reports a root the author chose not to list. Extend would make "do not exempt `README.md`" inexpressible, and an author writing `entryPoints` at all is naming the roots they know | [GRP-002](../guide/rules/GRP-002.md) | [P13.04](P13-correctness/04-rule-option-defaults.md) |
| "A Markdown file" is `.md` + `.mdx` and nothing else: neither is linted beyond `.md` by default, and a linked `.markdown` file is invisible to the coverage signal even though it exists on disk | One definition for the coverage signal, the `init` scan, and the default `include` is the whole point of W-09 — three sets meant coverage checked for an extension no default config could admit and missed the one `init` walks. `.markdown` appeared nowhere else in core and on no guide page, so recognizing it could never lead anywhere; adding `.mdx` to the linted corpus is a parser-implicating product decision this task holds out of scope, so the gap is a declared subset (`LINTED_MARKDOWN_EXTENSIONS ⊆ MARKDOWN_EXTENSIONS`) rather than three literals | [Context graph](../guide/context-graph.md#algorithms) (coverage caveat) | [P13.05](P13-correctness/05-reference-resolution.md) |
| An MCP argument the tool's own `inputSchema` rejects is refused before the handler runs, so it comes back as `isError: true` with **no `structuredContent`** and raw transport text carrying the JSON-RPC `-32602` number — outside the `{ code, message, hint }` contract entirely | Closing it means loosening every tool's advertised `inputSchema` to accept shapes it intends to reject, purely so the handler can reject them better — and that schema is what a host or model reads to _construct_ a valid call. The loosening is instead selective, aimed at the mistakes that need guiding advice ([P12.04](P12-consistency/04-mcp-custom-rules.md)'s `custom` entry union), which is the honest form of the trade. The exempt text does still name the offending field and its constraint, so a human or a model can act on it | [MCP server](../guide/mcp-server.md#error-contract) (the branch-on-`isError` note), [Glossary](glossary.md) **Error contract** | [P14.05](P14-host-boundary/05-mcp-error-contract.md) |
| An MCP `OPERATIONAL_ERROR` names only a path **inside** the tool's `cwd`: an errno whose path escapes it, or that reports no path at all (POSIX `EISDIR` from a `read`, `ENOSPC`), stays a sanitized `INTERNAL_ERROR` — where the CLI renders the `../` chain and keeps the original message | The bounded half of [W-21](remediation-backlog-2026-08-05.md)'s fix, and the reason it is safe to add a code that carries a path at all: "no payload names a host path _outside_ the analyzed directory" is the property `INTERNAL_ERROR`'s sanitization exists for — that directory itself is the one absolute path any payload carries, and only where [P14.01](P14-host-boundary/01-mcp-cwd-validation.md)'s `INVALID_INPUT` echoes back the `cwd` it could not use — and across Windows drives `path.relative` returns an absolute path outright. The CLI can afford the opposite choice because its output is a terminal, not a machine contract that a model may echo | [Output & exit codes](../guide/output.md#operational-failures-on-both-hosts) | [P14.05](P14-host-boundary/05-mcp-error-contract.md) |
| Config validation does not aggregate across its two stages: a file with both a shape error and a rule-options error reports only the shape error, so clearing it takes two runs | Stage 2 resolves rules from stage 1's _parsed_ output, so running it on a shape the schema rejected would feed `resolveRule`/`resolveCustomRule` inputs they are not typed for — the crash class audit M-3 closed. Each stage does report all of _its own_ issues at once, so the bound is two passes, not one error per run | [Configuration](../guide/configuration.md#validation--errors) | [P13.06](P13-correctness/06-config-diagnostics.md) |

## Recorded residuals

Known, narrow, and not fixed. These are maintainer-facing: no user action closes them, so they cite their task file rather than a guide page. Listed so a later sweep re-finds them as _known_ rather than filing them again.

| Residual | Why not fixed | Recorded in |
| --- | --- | --- |
| A `STR-001` literal whose filename is itself glob syntax (`LICENSE(1)`, `docs[x]/a.md`) is classified as a glob and routed to the corpus branch, so a non-Markdown file at that path still reports missing | Unchanged pre-existing behavior (every entry took the corpus branch before P11.12), needs a filename that is glob syntax, and the fix would be an escaping vocabulary the option does not have | [P11.12](P11-remediation/12-str001-reach.md) |
| `candidateEscapesRoot` does not repeat `resolvesOutsideRoot`'s resolve-and-compare step, so a candidate normalizing to a bare drive-relative remainder (`c:secret.md`) on a different drive than the root is not caught at the three `existsSync` call sites | Reaching it needs an attacker-authored document, a Windows host, and a `..`-cancellation leaving a bare drive letter with no root separator — materially narrower gain than the fix that shipped. `SEC-003`'s `template` is fully covered | [P11.02](P11-remediation/02-sec003-path-escape.md) |
| A gitignored workspace package is still detected by `init` and still produces a (empty) scan scope; the gitignore layers are threaded only through the Markdown walk, not through workspace-package detection | The asymmetry is invisible in the draft — an empty scope proposes nothing — and workspace detection reads `package.json` files, which `.gitignore` rarely speaks about deliberately | [P11.14](P11-remediation/14-init-cli-lows.md) |
| The `init` draft a user confirms does not name the project-local `schema.json` the `npx` path writes; only the after-the-fact write summary does | A gap against the warn-before-confirming discipline, explicitly **deferred** rather than accepted — the one row here a future task should close rather than keep | [P11.14](P11-remediation/14-init-cli-lows.md) |
| `init`'s `GRP-001` rationale can cite a sampled two-document cycle beside an entry that, at `minCycleLength`'s default of 3, will not report it — the proposed config is valid, but its own comment describes a finding the run will not produce | The inference heuristic and the rule's finding floor moved in different changes; [P13.04](P13-correctness/04-rule-option-defaults.md) is scoped to the config-authoring path and touching inference belongs with the rest of `init`'s widening (W-39/[P16.05](P16-release-readiness/05-low-severity-cleanups.md)). Narrow because it needs a sampled back-link, and the config it writes is correct either way | [P13.04](P13-correctness/04-rule-option-defaults.md) |
| A `siteRouter` with no known `preset` (a bare `{}` included) returns the stripped URL **un-normalized**, so `/gen/../generated/x.md` yields the candidate `gen/../generated/x.md` where the no-router branch yields `generated/x.md`. `existsSync` still resolves it, but an `exclude` glob written against the normalized path does not match it | Narrow (needs a `..` segment inside a root-relative target _and_ a router set) and pre-existing — outside W-08, whose defect was `exclude` not being consulted at all. `resolveTargetCandidates` is read by three subsystems, so normalizing the unknown-preset branch is a shared-behavior change that wants its own task rather than a rider on a shared branch | [P13.05](P13-correctness/05-reference-resolution.md) |
| The absolute-path fallback for an out-of-`cwd` target is scoped to `compile`'s write summary, so argument diagnostics (`resolveDirectoryArgument`) and the errno backstop (`formatOperationalError`) still render a path above `cwd` as a `../` chain | Widening it would reverse [P11.10](P11-remediation/10-cli-exit-contract.md)'s deliberate promise that a `[path]` passed absolutely is _reported_ relatively, and would loosen the "an error never prints an absolute host path" property those surfaces are pinned on. A written file is the opposite case — the user has to open it. The asymmetry is narrow (an argument outside `cwd` at all) and nothing depends on the current rendering, so widening later stays cheap | [P14.02](P14-host-boundary/02-cli-exit-codes.md) |
| `init` recursively walks every pruned **hidden** tree to size it for the disclosure, so a hidden cache `DEFAULT_NOISE_DIR_NAMES` does not name (`.tox`, `.gradle`, `.mypy_cache`, `.pytest_cache`, `.terraform`, `.turbo`, `.nx`, …) gets a `readdir` plus a `.gitignore` probe per directory for a number the user is only told about. Being gitignored does not stop it either — `"hidden"` is classified before the gitignore test, which also decides how such a tree is _disclosed_: it appears on the hidden line and never on the gitignored one, so whatever Markdown the ignore patterns do not themselves match is counted and offered an `include` suggestion that the `respectGitignore: true` a fresh `init` writes will not honor | The bound is that name list, so it is incomplete by construction: `.venv`/`.yarn` cover the two trees the field test actually hit, and further names are a one-line addition when one shows up. The alternative — bounding by _shape_ rather than by name — is exactly what [P14.03](P14-host-boundary/03-init-disclosure.md) removed from the lint-time default, and here it would make the disclosed count silently wrong for the dot-directories W-14 exists to surface: a `.claude/skills/` reported as `0 Markdown files` is worse than a slow scan. Bounded to `init`, a one-off command, and never on the lint path | [P14.03](P14-host-boundary/03-init-disclosure.md) |
| The `--no-install` flag on the `npx` smoke check in `packages/cli/test/bin.e2e.test.ts` is load-bearing nowhere: it is an npx-v6 spelling the pinned npm parses as an unknown config. The check's `cwd` is the whole no-network guarantee | Harmless where it sits, and removing it is a test-hygiene cleanup rather than a behavior fix | [P11.01](P11-remediation/01-cli-bin-noop.md) |
