# P18.03 — Core behavior nothing currently proves

> Phase: [P18 — Follow-up burn-down](index.md) · Roadmap: [v2 Index](../index.md) · Size **M** · Status **Done**. Depends on [P18.02](02-code-fixes.md) (two of these pins describe behavior that task changes).
>
> Four gaps where a shipped behavior was carried only by a comment or by a single matcher-level test. Two of the six items originally grouped here were already closed: FU-21 asked for a fixture exercising a state the scan's registered dot-directory prune makes unreachable, and FU-23 was done in [P18.02](02-code-fixes.md) because it lives in the same file as FU-12 — see [the phase index](index.md).

## What was wrong, and what was done

- [x] **FU-18 — `selectBranch`'s non-discriminated fallback had no test.** `packages/core/src/config/config-issues.ts` picks the fewest-issues branch where the root schema offers no discriminator, and no config a user can write reaches it: the only other union is `assertionSchema`, a discriminated union whose no-match issue carries `errors: []` and is short-circuited by the `issue.errors.length > 0` guard in `collect`. [P13.06](../P13-correctness/06-config-diagnostics.md)'s notes state this; nothing pinned it, so a schema edit could break the branch silently. `flattenConfigIssues` is now driven directly in `config-v2.test.ts` with hand-built issues — two branches at a path that is not `["rules", n]`, asserting the shorter one is expanded, plus an `errors: []` issue passing through with its own message. Hand-built by necessity: constructing a genuine issue of that shape means finding a schema that produces it, which is exactly what does not exist.
- [x] **FU-19 — the item named a glob the tree no longer has; the gap under it was real and is now closed.** The follow-up asked for an end-to-end pin of `**/.*/**`, "the highest-impact half of the default exclude". That glob is **not** in the lint-time default and has not been since [P14.03](../P14-host-boundary/03-init-disclosure.md) removed it — the follow-up was recorded by the [P13.02](../P13-correctness/02-default-exclude.md) run that shipped it, and the decision was reversed a phase later. Its own 31% figure is now the argument _against_ shape-based exclusion, and `corpus-scope.ts` states it that way. Written as prescribed, the step would have asserted `.github/PR.md` is pruned, which is the opposite of what ships. **What survived the reversal is the shape of the gap**: the default was pinned at the matcher and not through a corpus entry point, so the wiring between `resolveCorpusScope` and the walk was proven for `node_modules` alone. `lint-files.test.ts`'s zero-`exclude` case now carries both directions of the decision end to end — `.venv/…` pruned because it is a dependency tree named in `DEFAULT_NOISE_DIR_NAMES`, `.github/PR.md` linted because a dot-directory that is neither dependency nor build output is not excluded for its shape. Adding `**/.*/**` back to the default now fails that test.
- [x] **FU-20 — two call sites gained the resolved default scope with no test.** `applyFixes` and `loadContext` both resolve it, so `--fix` no longer rewrites a document under a default-excluded tree and `graph`/`slice`/`impact` answer over the same corpus the lint does — two user-visible changes carried only by the comment "Same resolved scope as `lintFiles`". `lintFiles` is covered at two layers; these two were covered at none. Now one test each: `load-context.test.ts` asserts a config naming no `include`/`exclude` returns `docs/a.md` alone beside a `node_modules/pkg/README.md`, and `rules-tbl.test.ts` asserts a fixable table under `node_modules/` is left byte-unchanged by `--fix` while its sibling is rewritten. Both fail when the call site drops `resolveCorpusScope`.
- [x] **FU-22 — the count-mode walk was not compared against a corpus walk.** `repo-scan.ts`'s `"count"` mode is the same function re-entered under a pruned hidden root, so its noise, gitignore and extension handling cannot diverge from the collect walk's _today_ — but every existing assertion compares the disclosed number against a hand-written expectation, which would stay green if that branch were ever split into a walk of its own, and a divergence there is invisible: two plausible numbers, both green. `repo-scan.test.ts` now compares the disclosed `markdownFileCount` for a hidden tree against a real `loadDocuments` walk over the same directory under the lint-time defaults — a different implementation of the same three rules, following the precedent already in that file. The fixture makes all three fire to reach its count of 2 (a gitignored subtree, a non-Markdown file, a nested `node_modules`), and its `.gitignore` lives _inside_ the hidden tree, since one above it is read by the outer walk and not by a walk rooted at it.

## Notes

**FU-19 is the phase's standing lesson in its second form.** [P18.01](01-compile-renderers.md) found items that still reproduce and turn out to be registered decisions; this one still reproduced as a _documentation_ claim while the code had moved the other way. The register named the reversal in the `init`-scan row, and `corpus-scope.ts` carries the reasoning in full — checking either before writing the fixture is what stopped a test being written against behavior that was deliberately removed. The follow-up file has no dates and no status, so an item recorded before a decision reads exactly like one recorded after it.

**No documentation changed.** All four are test-only, and the behaviors they pin are already stated: the default exclude in [Configuration](../../guide/configuration.md#what-is-excluded-before-you-write-anything) and the [accepted-behaviors register](../accepted-behaviors.md), the two-stage validation bound in the same register, the `init` disclosure in [CLI reference](../../guide/cli.md#init).

## Exit criteria

- [x] Deleting the `selectBranch` fallback fails a test.
- [x] The default exclude is pinned at a corpus entry point in both directions, not only at the matcher — a dependency tree pruned by name, a dot-directory linted — so re-adding a shape-based default fails there.
- [x] `--fix` and `loadContext` each have one test asserting the default scope applies to them.
- [x] Count mode and a corpus walk are compared over one tree in one test.
- [x] `npm run format`, `npm run lint`, `npm run typecheck`, `npm run build`, `npm run lint:docs` and `npm test` all pass.
