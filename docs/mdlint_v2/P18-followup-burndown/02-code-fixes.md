# P18.02 — Twelve localized fixes across core, the CLI and the MCP host

> Phase: [P18 — Follow-up burn-down](index.md) · Roadmap: [v2 Index](../index.md) · Size **M** · Status **Done**.
>
> Twelve items, each one file and a bounded edit. They were one task because none is worth a task alone and no two touch the same file.

## What was wrong, and what was done

- [x] **FU-05 — the exported `Assertion` type required a key a caller should not have to write.** `z.infer` made `columnInSet.caseSensitive` **required** on every hand-written assertion once [P13.04](../P13-correctness/04-rule-option-defaults.md) gave it a `.default()`, breaking any consumer that builds an assertion or a `CustomRuleConfigEntry` literal — and contradicting `describe-rules.ts`, documented as receiving entries that never passed through Zod. Invisible to CI, because no tsconfig includes `test/**`, while the repo's own `rules-custom.test.ts` carries exactly such a literal. Now `z.input`, with the reason stated at the export: the runtime default and the `?? DEFAULT_COLUMN_IN_SET_CASE_SENSITIVE` fallback already cover `undefined`, and `describe-rules.ts`'s `=== false` test still holds.
- [x] **FU-06 — `init` annotated a config with a cycle that config would never report.** `rule-inference.ts`'s `GRP-001` rationale names a concrete sampled loop, but the entry it annotates carries no options, so `minCycleLength` is the schema default of 3 and a two-document loop is silent. Recorded as a residual whose fix belonged to "whoever next touches `rule-inference.ts`", with two options offered. **Took the first:** a cited cycle shorter than the rule's own floor now travels with `minCycleLength` lowered to that cycle's length. That keeps the concrete evidence — which the cross-cluster heuristic exists to produce — and makes the proposed config report it, rather than closing the gap by deleting the more useful half of the disclosure. Above the floor nothing is emitted, so the common case still proposes `GRP-001` bare. Pinned in both directions: two documents emits the option, three does not.
- [x] **FU-07 — an explicitly empty `cwd` was treated as omitted.** `path.resolve("")` returns `process.cwd()`, so `{"cwd": ""}` passed the stat guard and analyzed the server's own working directory — the plausible-answer-to-a-different-question failure the whole guard exists to name, and the one caller mistake it could not see. Now rejected before `path.resolve`, with the same `hint`. Deliberately not `.min(1)` on the tools' `inputSchema`s: a schema rejection is refused pre-handler as a bare `InvalidParams` with no `structuredContent` and no `hint`.
- [x] **FU-08 — the same guard's messages used native separators.** `cwd does not exist: C:\Users\…` on Windows, against a project-wide convention that user-visible paths are POSIX. Absolute-versus-relative here is deliberate and documented; the separator was not. A local one-line helper renders the message while the returned value stays platform-native, and the tests now build their expectation the same way, so the pin holds on Windows instead of passing only on POSIX.
- [x] **FU-09 — a gitignored hidden directory was disclosed as hidden.** `classifyPrunedDirName` ran before the gitignore test, so such a tree was recorded as `{reason:"hidden", markdownFileCount}` and offered the include pattern that fits that class — advice a fresh `init` config defeats by writing `respectGitignore: true` — while never appearing on the gitignored line that would explain why the pattern did nothing. The gitignore test now runs between `"noise"` and `"hidden"`, which also tightens the count walk's bound: such a tree is skipped rather than recursively sized. The one-reason-per-directory tie-break is now stated on `PrunedDirectoryReason` itself.
- [x] **FU-10 — the include disposition was derived twice from one three-valued rule.** The writer computed `include`, and the draft's disclosure independently computed the boolean form of the same decision; nothing tied them, so a later change to one would have made the disclosure claim the opposite of what was written. Extracted as `resolveIncludeToWrite`, used at the write site, with the disclosure asking it `!== undefined`.
- [x] **FU-11 — `classifyPrunedDirName` was on core's barrel with no importer.** `repo-scan.ts` imports it from the module directly and its sibling `isPrunedDirName` is deliberately unexported. Dropped from the barrel; the glossary entry stays, because it documents internal vocabulary.
- [x] **FU-12 — a test re-spelled the value a constant owns.** `schema-generation.test.ts` hardcoded `["README.md", "CLAUDE.md", "AGENTS.md", "index.md"]` while `DEFAULT_GRP002_ENTRY_POINTS` existed to be its single source, so the guard could not catch that value changing. It now reads the constant — which also gives that export its first importer.
- [x] **FU-13 — a module header stated a constraint its file no longer uniformly holds.** `operational-errors.ts` said "all three functions" (there are four) and promised no absolute platform-native path is ever printed, while `toWriteTargetPath` deliberately prints one. The header now names that exception and why, and `formatWriteFailure`'s parameter is `targetPath` rather than `relativePath`, since `handleCompile` passes a value that is absolute for an out-of-`cwd` target.
- [x] **FU-15 — the MCP host's comment named an expression that no longer exists.** `handleLintFiles` cited core's `include ?? ["**/*.md"]` fallback, moved to `resolveCorpusScope` at [P13.02](../P13-correctness/02-default-exclude.md). Retargeted, and extended with the consequence an agent actually hits: an explicit `patterns` naming a path under a default-excluded tree still resolves to nothing.
- [x] **FU-16 — the schema's `default` on `exclude` read as replace semantics.** In JSON Schema `default` means "the value used when the key is absent" — exactly the semantics [P13.02](../P13-correctness/02-default-exclude.md) rejected — and the editor tooltip is the one surface a user reaches without the guide. A `description` now states that entries are appended and that negating is the move that works. Regenerated, so `packages/cli/schema.json` and its byte-sync test stay green.
- [x] **FU-68 — `IgnoreLayer`'s contract omitted what its memoization depends on.** `isGitIgnored` caches ancestor-neutralized copies of a layer's `Ignore` under that object's identity, so mutating it after a first query would leave every cached answer stale. Both producers build a fresh `Ignore` per directory per walk, but nothing said so to a future producer. Now stated on the type, beside the array-ordering contract it already carried, and in the glossary entry.

## Notes

**Two of these were decisions, not defects, and were resolved as such.** FU-06 was a recorded residual that the register explicitly assigned to whoever next touched `rule-inference.ts`, with two acceptable fixes named; taking the option that keeps the disclosure concrete is a choice this task made and states. FU-09's ordering was half-recorded — the register described the walk-cost consequence but not the wrong-advice one — so the row was narrowed rather than deleted, and the register now says what the order is and why.

**Four documentation surfaces moved with the code**, in the same change: the register lost the `init`/`GRP-001` residual row and had its hidden-walk row narrowed; the glossary gained the `IgnoreLayer` mutation clause and the walk's three-way prune order; `docs/guide/mcp-server.md` gained the empty-`cwd` rejection and the separator rule; and the two owning phase files ([P13.04](../P13-correctness/04-rule-option-defaults.md), [P14.03](../P14-host-boundary/03-init-disclosure.md)) record which of their residuals this closed.

**FU-14 is not here and is not forgotten.** The third copy of the errno guard is a deliberate host-local judgment accepted at [P14.05](../P14-host-boundary/05-mcp-error-contract.md), whose recorded trigger is a _fourth_ copy. There are still three, so nothing is due.
